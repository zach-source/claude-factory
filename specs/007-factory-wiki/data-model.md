# Data Model: Factory wiki

## Wiki repo layout (`$HOME/wiki/`)

```text
wiki/
├── index.md                 # rigs and topics, newest solutions (refresh writes the rig list; write keeps topics)
├── glossary.md              # factory terms (seed; groom or a person keeps it)
├── needs-person.md          # flags: a person's line that a pass wanted to change (R7)
├── rigs/<rig>.md            # one per rig, fully generated by refresh
├── topics/<topic>.md        # topic overview + list of solution pages
└── solutions/<yyyy-mm>/<slug>.md
```

## Page (all kinds)

Frontmatter (YAML), then Markdown body. See [contracts/pages.md](contracts/pages.md).

| Field | Type | Rule |
|-------|------|------|
| `kind` | `rig` \| `solution` \| `topic` \| `index` \| `glossary` | required |
| `title` | string | required, plain words, no bead id |
| `rigs` | string[] | rig names it covers; required for `rig` and `solution` |
| `beads` | string[] | bead ids it covers (find, FR-015) |
| `prs` | string[] | PR URLs it covers |
| `topics` | string[] | topic slugs; `solution` needs at least one |
| `status` | `current` \| `superseded` \| `stale` | default `current` |
| `superseded_by` | path | required when `status: superseded` (FR-016) |
| `cause` | `proven` \| `hypothesis` | `solution` only (FR-005) |
| `updated` | ISO time | set by the factory on each factory commit |

**History** is git: each commit records the author (factory identity or a person) and a message `wiki <pass>: <why>` (FR-011).

## Rig page (generated)

Sections in this order (FR-001): `Waits on a person`, `In progress`, `Queued`, `Shipped (last 7 days)`, `Stopped (last 7 days)`, then `Last update: <ISO>` (FR-003).

**Work item** (one line + one indented line):

| Field | Source |
|-------|--------|
| summary | bead title + first sentence of the last report, prefix `node#n outcome:` stripped |
| step | `row().value` → station name linked to the glossary |
| age | now − run start |
| links | bead id, PR URL, solution page if one exists |
| question (waiting only) | the `Question:` line of the report; who answers: "owner" |

State mapping:

- A live run that is not waiting goes in In progress.
- A `waiting()` row goes in Waits on a person.
- A ship queue item without a live run goes in Queued.
- A PR merged in the last 7 days goes in Shipped.
- A run that ended `aborted` or `stopped` in the last 7 days goes in Stopped. Its reason is the last summary.

## Solution page

Body sections, in order (FR-005): `Problem`, `Cause`, `Change`, `Options rejected`, `Verification`, `Still open`, `Links`. A `Cause` with `cause: hypothesis` says what would prove it.

## Pass state (`$HOME/wiki-state.json`)

```json
{
  "lastWriteAt": "ISO",
  "written": { "<bead id>": "<page path>" },
  "visibility": { "value": "PRIVATE", "checkedAt": "ISO" },
  "groomPr": { "url": "…", "branch": "groom/2026-11-06", "openedAt": "ISO" },
  "tombstones": [{ "path": "solutions/…", "at": "ISO" }]
}
```

- `written` keeps a bead from a second page; a later bead on the same PR updates that page.
- Not tracked in the wiki repo (it is home state, like `sweeps.json`).

## Write input item

`{ beads: [{id, title, closeReason, comments}], prs: [{url, title, body, files}], reports: Entry[], rig }` — one per group of beads that share a PR (R5). At most 20 per pass; the rest wait for the next pass, oldest first.

## Grooming pass

```text
none ──(daily, no open groom PR)──▶ planned ──▶ applied on groom/<date> ──▶ PR open
PR open ──(person merges)──▶ none          PR open ──(person closes)──▶ none
```

**Plan line**: `<merge|rewrite|stale|supersede> <path>[ <path2>] — <reason>`; at most 15 lines (`GROOM_CAP`, env `FACTORY_WIKI_GROOM_CAP`). The factory reverts each path that changes outside the plan, before the commit.

## Validation rules

- The factory must not commit a page with a `secretFile()` match (FR-013).
- A factory commit must not change a line that a person wrote, as shown by the blame author (FR-012). For such a page, return the page to its earlier version and add a `needs-person.md` flag.
- A factory commit must not create a tombstoned path (FR-017).
- The factory must not push when the cached visibility is not `PRIVATE`/`INTERNAL` (FR-014).
- If a `solution` page has a missing required section, `scanPages()` rejects the page. The factory does not commit it, and the item waits for the next pass.
